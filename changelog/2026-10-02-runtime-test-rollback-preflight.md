# Runtime Read TEST: rollback y comprobación de los dos roles

El `Deploy Test` protegido `37076527573` falló al ejecutar el único cambio de `ConfigRuntimeReadFunction.Code` revisado en `37076030592`. El evento de CloudFormation mostró `AccessDenied` para `s3:GetObjectVersion`: el rol `zoolanding-config-runtime-read-test-cfn-exec` no podía leer la versión del ZIP bajo el SHA TEST `06b38c243ed5df6a1bd94a6d2cffd0b9c692b34f`. El rol GitHub ya tenía el prefijo de ese SHA. CloudFormation terminó en `UPDATE_ROLLBACK_COMPLETE`; los ocho recursos permanecieron y el alias `live` conservó la versión 4.

El operador rechazaba ese estado antes de crear una nueva revisión. Ahora admite el rollback completo **solo en TEST** si verifica el rol, el StackId, las ocho identidades y sus estados completos, y la ausencia de change sets. La verificación existente de plantilla, parámetros, configuración, alias y bytes del paquete continúa aplicándose. El estado de la pila entra en el snapshot sellado del review. Estados de rollback en curso o fallido siguen rechazados.

`tools/runtime_test_preflight.py` realiza consultas de solo lectura antes de un Action manual. Comprueba SHA y árbol TEST, selector, workflow, cuenta, región, paquete, pila, versión S3 y decisiones IAM de los roles GitHub y CloudFormation. También comprueba que los permisos no alcancen otra ruta y que la escritura siga limitada a AES256. Las pruebas reproducen el caso donde GitHub está permitido y CloudFormation denegado.

La corrección IAM propuesta todavía no está aplicada: sus dos documentos se generaron localmente desde las políticas vigentes y cambian solo tres recursos en la política del rol GitHub y uno en la del rol CloudFormation al prefijo de releases TEST. La simulación de los candidatos pasó. El replay completo con AWS real y esos candidatos pasó; el preflight con IAM real se detuvo por el permiso faltante del rol CloudFormation. Cualquier actualización IAM, push y nuevo review/execute siguen sujetos a autorización separada.
